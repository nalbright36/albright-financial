No-JS fallback: each tab is its own real
with no explicit action, so a native submit always POSTs back to whatever page it's actually on - correct for the full Calculators page (its own "Calculate" button re-renders it with server-computed results, from calculator_views._buy_result()/_ebay_result(), both backed by scanner/simple_calc.py). The dialog has no real no-JS story anyway (a needs JS's showModal() to even open), so there's deliberately no action pointing elsewhere for it to fall back to - these forms must never be able to navigate the dashboard away to a different page. With JS, the same fields are read live and posted to calculate_api instead, debounced, so results update as you type - either way goes through the exact same simple_calc functions, so they can never disagree. {% endcomment %}
